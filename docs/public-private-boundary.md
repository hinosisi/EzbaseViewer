# 공개·비공개 경계

## 기본 원칙

EzbaseViewer의 제품 소스는 공개하되, Ezbase 내부 시스템에 직접 접근하는 구현과 운영 데이터는 공개 저장소에서 분리한다. 공개 여부와 네트워크 노출 여부는 별개로 관리한다. 공개된 서버 코드라도 Ezbase 내부 연동 API는 사설망과 서비스 인증을 모두 통과해야 한다.

## 정보 등급

| 등급 | 저장 위치 | 포함 항목 | 배포·접근 원칙 |
|---|---|---|---|
| `PUBLIC-APACHE` | `hinosisi/EzbaseViewer` | 중립 API 계약, 제어 서버, 시험 코드, 빌드 스크립트, 공개 설계 문서 | Apache-2.0으로 공개 |
| `PUBLIC-AGPL` | 별도 RustDesk 포크 저장소 | RustDesk Client·Server 원본, HostOnly·Viewer 변경, 대응 소스와 빌드 방법 | AGPL-3.0과 원 저작권 고지를 유지해 공개 |
| `INTERNAL` | 비공개 Ezbase 연동 저장소 | Ezbase 내부 API·DB·SSO 어댑터, 실제 필드 매핑, 내부 주소, 배포 토폴로지 | 승인된 개발·운영자만 접근 |
| `RESTRICTED` | 비밀관리·감사 시스템 | 운영 비밀번호·토큰·개인키·서명키, 인증서, 고객/장치/사용자 데이터, 실제 감사·장애 기록 | Git 저장 금지, 최소권한과 접근 감사 적용 |

## Ezbase 내부 접근 경계

공개 저장소에는 `사용자`, `조직`, `업체`, `장치`, `권한`, `일회용 실행 코드`와 같은 중립 계약만 둔다. 다음 구현과 자료는 비공개 영역에만 둔다.

- Ezbase 내부 API URL, DB 스키마·접속 문자열과 네트워크 구성
- Ezbase SSO·세션·사용자·조직·업체 식별자를 변환하는 실제 어댑터
- 운영용 서비스 계정, 인증서, 토큰, 허용 IP와 방화벽 규칙의 실제 값
- 고객별 설정, 내부 장애 기록, 원본 로그와 지원 자료

공개 제어 서버의 Ezbase 내부용 엔드포인트는 다음 두 조건을 모두 요구한다.

1. 요청의 실제 연결 주소가 루프백, RFC1918 IPv4, IPv6 ULA 또는 링크 로컬 범위다.
2. `X-Ezbase-Internal-Key` 서비스 인증이 성공한다. 이 키는 PoC 최소 구현이며 운영 전 mTLS 또는 동등한 워크로드 신원 인증으로 강화한다.

애플리케이션은 임의의 `X-Forwarded-For` 값을 신뢰하지 않는다. 리버스 프록시를 사용할 때는 운영 비공개 구성에서 신뢰할 프록시를 명시하고 외부 경로가 내부 엔드포인트로 라우팅되지 않게 한다. 방화벽·보안 그룹에서 인터넷 인바운드를 차단하며, 애플리케이션 검사는 그 통제를 보완한다.

## 저장소 구성

```text
PUBLIC  hinosisi/EzbaseViewer
        ├─ 공개 제어 서버와 중립 계약
        ├─ 공개 시험·문서·설정 예시
        └─ 실제 Ezbase 어댑터와 운영값 없음

PUBLIC  hinosisi/EzbaseViewer-rustdesk (생성 예정)
        ├─ RustDesk 기반 Viewer/HostOnly 변경
        ├─ RustDesk Server 변경
        └─ AGPL 대응 소스·빌드 절차

PRIVATE EzbaseViewer-internal (생성 예정)
        ├─ Ezbase 내부 연동 어댑터
        ├─ 내부 계약 매핑과 배포 자동화
        └─ 비밀 값은 포함하지 않고 비밀관리 참조만 보관

VAULT   조직 비밀관리 시스템
        └─ 운영 키·인증서·비밀번호·고객별 비밀
```

비공개 저장소의 코드를 공개 저장소 프로젝트가 빌드 시 직접 참조하지 않는다. 런타임의 사설 서비스 계약으로 연결해 공개 빌드를 비공개 자료 없이 재현할 수 있게 한다.

## 공개 반입 검사

공개 저장소에 변경을 올리기 전에 다음 명령을 실행한다.

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\check-public-boundary.ps1
```

검사는 비공개 전용 디렉터리, 비밀 파일 형식과 대표적인 키 패턴을 차단한다. 같은 검사는 공개 저장소의 Pull Request와 `main` 푸시에서도 실행한다. 자동 검사에 통과해도 사람 검토를 생략하지 않는다. 내부 명칭·URL·스키마·고객 데이터가 발견되면 커밋하지 않고 비공개 저장소로 이동한다.

## 변경 승인

- 공개 계약 변경: 기술 책임자와 보안 담당 검토
- Ezbase 내부 어댑터 변경: Ezbase 담당자와 보안 담당 검토
- RustDesk 포크 변경: 기술 책임자, 보안 담당과 라이선스 담당 검토
- 정보 등급 변경: 제품 책임자와 보안·법무 승인 후 이 문서와 ADR 갱신

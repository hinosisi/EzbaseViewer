# REA 준비 및 사용 절차

현재 개발 PC 확인 결과 Node.js 24.11.1과 npm 11.6.2는 준비되어 있다. 2026-10-21 npm 공식 레지스트리의 `rea-agents` 현재 버전은 6.7.0이며, `npx -y rea-agents@6.7.0 --help` 기동에 성공했다. 전역 `rea` 명령과 Codex MCP 등록은 아직 구성하지 않았다.

`doctor --client codex` 결과는 다음과 같다.

- Windows x64와 Node.js 24.11.1: 정상
- Codex의 `C:\Users\admin\.codex\config.toml` REA 등록: 없음
- REA skill identity: 없음
- Ghidra: `GHIDRA_INSTALL_DIR` 미설정
- Hopper·IDA 등 네이티브 분석 제공자: 미구성

`setup --client codex --dry-run`은 Codex config에 `npx -y rea-agents@6.7.0 mcp` 등록을 추가하고, `C:\Users\admin\.agents\skills\reverse-engineer-anything`에 REA 스킬을 설치하며, 기존 config의 백업을 만드는 변경을 제안했다. 실제 적용은 전역 사용자 설정을 변경하고 Codex 재시작이 필요하므로 후보 바이너리와 분석 권한을 확보한 뒤 별도 승인 단계에서 수행한다.

## 설치 전 확인

1. 분석 대상과 질문, 업무 목적, 분석 권한을 승인한다.
2. REA 공식 저장소와 npm의 실제 최신 버전을 확인한다.
3. 정확한 버전을 기록하고 설치 변경 내역의 dry-run을 검토한다.
4. 네이티브 분석이면 승인된 Ghidra/Hopper/IDA와 JDK의 Windows 지원을 확인한다.
5. 분석 전용 VM 스냅샷을 만든다.

## 재현 가능한 설치 예시

아래 `<검증버전>`은 분석 시작 때 npm 공식 레지스트리에서 다시 확인해 정확한 버전으로 바꾼다. 현재 확인값은 `6.7.0`이다. `latest`를 분석 기록에 사용하지 않는다.

```powershell
npx rea-agents@<검증버전> setup
rea --help
```

설치가 끝난 뒤 연결된 도구 목록과 실제 입력 스키마를 기록한다. 패키지 설치 성공만으로 Ghidra 등의 분석 제공자가 준비되었다고 판정하지 않는다.

## 프로젝트 내 증거 보관 규칙

- 업체 파일과 바이너리는 이 저장소에 커밋하지 않는다.
- 분석 기록에는 파일명, 제품 버전, SHA-256, 서명자, 허가 근거를 적는다.
- 원본 출력에 토큰·개인정보가 있으면 접근 제한 저장소에 두고, 문서에는 마스킹된 발췌와 위치만 남긴다.
- `관측 사실`, `추론`, `미확인`, `반증`을 분리한다.
- 설계 결정에 사용할 결론은 실제 Windows 재현 시험과 동료 검토를 통과해야 한다.

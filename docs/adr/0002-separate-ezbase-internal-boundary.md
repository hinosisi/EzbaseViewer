# ADR-0002: Ezbase 내부 연동의 비공개 경계

- 상태: 승인
- 결정일: 2026-10-21
- 결정자: 제품 책임자

## 배경

EzbaseViewer 제품 소스는 공개하지만 실제 Ezbase 내부 API·DB·SSO와 운영 토폴로지는 공개하거나 인터넷에서 직접 접근할 수 없어야 한다. 공개 RustDesk 포크에는 AGPL-3.0 의무도 적용된다.

## 결정

저장소와 런타임 경계를 함께 분리한다.

1. 공개 `EzbaseViewer` 저장소에는 중립 계약, 제어 서버, 공개 시험과 문서만 둔다.
2. RustDesk 변경 소스는 별도 공개 AGPL 포크에서 관리한다.
3. 실제 Ezbase 내부 API·DB·SSO 어댑터와 필드 매핑은 별도 비공개 저장소에서 관리한다.
4. 운영 키·인증서·고객 데이터와 실제 로그는 Git이 아닌 비밀관리·감사 시스템에 저장한다.
5. Ezbase 내부 엔드포인트는 사설 연결 주소와 서비스 인증을 모두 요구하고 인터넷 라우팅에서 제외한다.
6. 공개 프로젝트는 비공개 어댑터를 빌드 의존성으로 참조하지 않고 런타임의 사설 서비스 계약으로 연결한다.

현재 PoC의 `X-Ezbase-Internal-Key`는 서비스 인증 최소 구현이다. 운영 전에는 신뢰 프록시를 명시하고 mTLS 또는 동등한 워크로드 신원 인증으로 강화한다.

## 결과

- 공개 소스 빌드는 Ezbase 내부 자료 없이 재현할 수 있다.
- 공개 저장소 유출만으로 Ezbase 내부 주소·스키마·자격 증명을 얻을 수 없다.
- 공인 주소에서 내부 엔드포인트에 접근하면 애플리케이션이 거부한다.
- 방화벽·사설 라우팅·서비스 인증·애플리케이션 검사를 함께 운영해야 한다.

## 검증

- `PrivateNetworkPolicy`가 루프백·허용 사설 범위만 승인하는 자동시험
- 내부 API의 서비스 키 검증과 HTTP 스모크 시험
- `scripts/check-public-boundary.ps1`의 금지 경로·파일·대표 비밀 패턴 검사
- 공개 전 Git 전체 이력과 배포 산출물에 대한 별도 비밀정보 검사

## 재검토 조건

- Ezbase 공식 연동 규격과 신원 인증 방식 확정
- 공개/비공개 저장소 간 빌드 또는 런타임 결합 방식 변경
- 리버스 프록시·클라우드 네트워크 구조 변경
- RustDesk 포크 또는 EzbaseViewer 라이선스 변경
